### Q1. What information is stored in the resource report?

The resource report records datapath information generated by synthesis.
Roughly, for each module / hierarchy it tells Conformal:

Which datapath cells were created (e.g. DW01_add, DW_leftsh, DW_cmp, DP_OP_xxx).

Which RTL operations they implement (add, sub, shift, compare, etc., with file and line number).

The bit-width / parameters of each operator.

Sometimes the datapath equation (e.g. O1 = I1 + I2 - I3) and notes about extraction.

The chosen implementation style (e.g. area-optimized).

### Q2. What is the difference between **Basic flow** and **MDP flow**?

In the basic flow, Conformal only sees the gate-level netlist.
Datapath recognition is done purely inside Conformal using
analyze multiplier and analyze datapath -merge -share -flowgraph ....
The tool tries to infer adders/multipliers/resource sharing directly from gates, which may lead to many aborts, long runtime, and unstable quality on large datapath-heavy designs.

In the MDP (Module-based Datapath) flow, synthesis and LEC work together:

Synthesis keeps module/datapath boundaries and generates a resource report (report_resources).

Conformal runs
analyze datapath -module -resourcefile $RESRC_FILE ...,
so it uses the resource report as a guide to recognize datapath components at the module level, instead of guessing everything from gates.

As a result, MDP flow:

has more accurate datapath modeling,

reduces aborts and improves “quality evaluated xx% success”,

and scales better to large designs like the CNN accelerator.


   
### Q3. What does `quality evaluated xx% success` mean?

The message
quality evaluated xx% success
appears during datapath analysis (e.g. for a multiplier block).
It is an internal quality metric that indicates how much of the target datapath structure has been successfully recognized and abstracted by Conformal.
